About CryptoVault

A multi-algorithm encryption and decryption platform built to demonstrate, compare, and make cryptographic techniques accessible for learning and practical use.

Project Overview

What CryptoVault is, what it does, and why it was built.

🎯

Problem Statement

Sensitive information is often transmitted and stored as plain text, making it vulnerable to unauthorized access and cyberattacks. Many users find encryption techniques difficult to understand and use. CryptoVault provides a simple, unified platform to address both of these challenges.

💡

What Makes It Novel

Unlike tools that focus on a single algorithm, CryptoVault combines multiple classical and modern cryptographic techniques into one web-based platform — allowing users to encrypt, decrypt, and directly compare algorithms based on their security, output, and performance.

🛡️

Supported Algorithms

Classical: Caesar Cipher, ROT13, Atbash, Vigenère.
Encoding: Base64.
Modern: AES-256-CBC (symmetric encryption), SHA-256 (cryptographic hash). More algorithms can be added as the project evolves.

⚙️

Tech Stack

Frontend: HTML5, CSS3, JavaScript (ES6+) — no frameworks, no dependencies.
Backend: PHP 8 — handles AES-256-CBC and SHA hashing via OpenSSL.
Tools: VS Code, Git/GitHub.

📊

Algorithm Comparison

The Compare page runs all 7 algorithms on the same input simultaneously, displaying encrypted output, output length, and execution time in a table and visual bar charts — making it easy to see the practical differences between techniques.

🔒

Ethical Scope

CryptoVault is a controlled, educational platform. It does not involve penetration testing, vulnerability assessment, or the collection of personal data. All operations run locally in the user's browser or on their own PHP server.

Research Objectives

Five clear, specific goals this project aims to achieve.

  • Develop a user-friendly platform that encrypts and decrypts text using multiple cryptographic algorithms within a single interface.
  • Implement and compare different encryption techniques based on security level, processing time, and output characteristics.
  • Ensure that encrypted data can be correctly decrypted only through the appropriate algorithm and key or method.
  • Provide users with a simple interface for selecting an algorithm, entering text, and generating encrypted or decrypted results instantly.
  • Demonstrate the practical use of cryptographic techniques for protecting sensitive information from unauthorized access.

Expected Outcome

What this project delivers.

Functional Prototype of CryptoVault

A user-friendly, web-based platform that provides secure text encryption and decryption using multiple cryptographic algorithms. Users can enter text, select an algorithm, generate encrypted output, and decrypt it when required.

The platform demonstrates and compares the basic working and security characteristics of different encryption techniques — providing a practical solution for secure information handling and cryptography education.

The system validates that encrypted data can only be recovered through the correct algorithm and key, reinforcing fundamental principles of confidentiality and access control.

How to Run

Two options depending on whether you need AES and SHA (PHP required) or just classical algorithms (browser only).

🌐

Option A — Static (Browser Only)

Open index.html directly in any modern browser. Caesar, ROT13, Atbash, Vigenère, and Base64 all work without a server. AES and SHA will show a server-not-available notice.

🖥️

Option B — PHP Server (Full Features)

Serve the project through a local PHP server:

  • XAMPP / WAMP — place folder in htdocs/
  • PHP built-in server — run php -S localhost:8000 in the project folder

All 7 algorithms including AES-256 and SHA-256 will be fully functional.

⚠ Educational Disclaimer

CryptoVault is built strictly for educational purposes as part of an academic minor project in Cybersecurity. The classical ciphers (Caesar, ROT13, Atbash, Vigenère) are historically significant but not secure for protecting real sensitive data.

For production security needs, always use vetted, up-to-date cryptographic libraries and consult current security standards (e.g. NIST guidelines). Do not use this platform for encrypting genuinely sensitive information in a production environment.
